MAINZWORLD OUTSIDE-VSCODE RUNBOOK
=================================

VS Code is only the editor. The app can be run from Terminal and opened in any browser.


LOCAL MAC USE
-------------

1. Open Terminal.

2. Start the frontend from the actual Vite project directory:

   cd /Users/mains/AppDev/MainzWorld/frontend
   npm run dev -- --host 127.0.0.1

3. Open any browser and visit:

   http://localhost:5173

The frontend uses the PHP API at:

   http://localhost:8080

The local API is served by Apache from:

   /Users/mains/AppDev/MainzWorld/api/public

Do not run "npm run dev" from /Users/mains/AppDev. That folder does not contain the frontend package.json.

The equivalent command from any directory is:

   npm --prefix /Users/mains/AppDev/MainzWorld/frontend run dev -- --host 127.0.0.1


START LOCAL SERVICES
--------------------

If the services are not already running:

   brew services start postgresql
   brew services start php
   brew services start httpd

Check service status:

   brew services list

Check PostgreSQL:

   pg_isready

Check the API:

   curl -i http://localhost:8080/api/v1/auth/me

A response of 401 Not logged in means the API is reachable but the browser has no active session. It is not a server-startup failure.


DATABASE ENVIRONMENT
--------------------

The PHP API reads these environment variables:

   MAINZWORLD_DB_HOST
   MAINZWORLD_DB_PORT
   MAINZWORLD_DB_NAME
   MAINZWORLD_DB_USER
   MAINZWORLD_DB_PASSWORD

The optional market API key is:

   TAAPI_API_KEY

Use the template at:

   api/.env.example

Do not put real passwords, API keys, or database credentials in Git, frontend code, or committed config files.


DATABASE MIGRATIONS
-------------------

Migrations are in:

   api/migrations/

Apply them in order to a configured database. The transaction-import idempotency migration is:

   api/migrations/017_transaction_import_idempotency.sql

That migration adds a per-budget transaction fingerprint and a unique index so the same import can be repeated without duplicating rows. It keeps the first copy of exact duplicate imported rows and does not remove manual transactions.

The migration was applied to the current local database and verified:

   import_fingerprint column exists
   unique fingerprint index exists
   159 existing imported rows were fingerprinted
   0 duplicate fingerprint groups remained

The API import response is:

   {"imported": 0, "skipped_duplicates": 159}

The UI displays:

   Imported 0 transactions. Skipped 159 duplicates.

If the API returns an unexpected response, check that Apache/PHP-FPM is serving the current MainzWorld/api source and that the migration has been applied.


CSV AND EXCEL IMPORTS
---------------------

Supported file types:

   .csv
   .xls
   .xlsx

Required fields are flexible and case-insensitive:

   Date, Transaction Date, Posted Date, Posting Date, or Post Date
   Description, Transaction Description, Memo, Details, or Name
   Either Amount, or Debit/Credit

Recognized optional fields include:

   Merchant, Payee, Vendor
   Account, Account Number, Account Name
   Category, Transaction Category
   ChkRef, Check Ref, Check Reference, Reference, Reference Number
   Balance, Running Balance
   Withdrawal, Deposit, Money In, Money Out

Headers may be in any order. Punctuation and capitalization are normalized.

If required columns are missing, the import fails with a validation error.

If the bank does not provide a separate transaction ID or reference column, the original description is preserved exactly. A trailing number embedded in a description, such as:

   KROGER #827 POS CONNERSVILLE IN US 108765

remains part of the description. It is not guessed to be a formal transaction ID.

Recurring subscription transactions are separate transactions because their dates differ. Re-importing the same transaction is skipped using its fingerprint.

The fingerprint uses date, description, merchant, amount, account, reference, debit, and credit. Running balance is intentionally excluded because it can change between exports.


PUBLIC HOSTING
--------------

For a real web-hosting deployment:

1. Build the frontend:

   cd /Users/mains/AppDev/MainzWorld/frontend
   npm ci
   npm run build

2. Install API dependencies:

   cd /Users/mains/AppDev/MainzWorld/api
   composer install --no-dev --prefer-dist --optimize-autoloader

3. Configure the host:

   frontend document root: /path/to/MainzWorld/frontend/dist
   API document root: /path/to/MainzWorld/api/public
   API path: /api

4. Configure PHP 8.1 or newer with PDO PostgreSQL enabled.

5. Configure PostgreSQL and the MAINZWORLD_DB_* environment variables.

6. Apply database migrations in order.

7. Enable Apache rewrite support.

The API route fallback is:

   api/public/.htaccess

The React Router fallback is copied into the frontend build from:

   frontend/public/.htaccess

The frontend API client uses relative URLs under /api/v1. Same-domain hosting is recommended because it keeps API requests, CORS, and PHP session cookies simpler.

For a host that cannot run Node or Composer, create a release package containing:

   frontend/dist/
   api/vendor/
   api/public/
   api/src/
   api/migrations/

Those generated folders are intentionally ignored by Git by default.


NETWORK TESTING FROM ANOTHER DEVICE
-----------------------------------

Start Vite on the network interface:

   cd /Users/mains/AppDev/MainzWorld/frontend
   npm run dev -- --host 0.0.0.0

Find the Mac's local IP:

   ipconfig getifaddr en0

From another device on the same network, open:

   http://YOUR_MAC_IP:5173

This is for temporary local testing only. API host configuration, session cookies, firewall rules, and CORS may need adjustment.

---------------
